# 决策模型对比测试报告：julia_1 vs laya-multilingual（1+1 / 10+11）（2026-11-17）

## 一、julia tokenizer.json 正确性验证（问题 1）

**结论：tokenizer.json 文件完全正确，不是结果偏差的原因。**

| 验证项 | 结果 |
|---|---|
| 与官方 HF 仓库（`SupersonicLabs/Julia-1` → `tokenizer/tokenizer.json`）逐字节对比 | **MD5 完全一致**（`8b0c0f40058fd77c07ec9d0459f148f4`，34,363,188 字节） |
| token 级编码对比（7 组中英文文本，含 `1+1等于几`、`10+11等于几`） | **全部 MATCH** |
| 特殊 token | `<pad>=0, <eos>=1, <bos>=2, <unk>=3, <mask>=4`（与官方 `tokenizer_config.json` 一致：cls=`<bos>`=2、sep=`<eos>`=1、mask=4） |
| 词表 | 256,000（gemma 族 Metaspace 词表） |

### 偏差的真正来源：GGUF 内嵌 tokenizer 元数据（非 tokenizer.json）

julia GGUF 内嵌的 tokenizer 元数据声明 `model=gpt2, pre=mmbert`。若按 `gpt2` 用 ByteLevel 预分词重建（tokenizer.json 缺失时的兜底路径），token 序列**完全错误**：

| 输入 | GGUF 重建（错误路径） | 官方 tokenizer.json |
|---|---|---|
| `1+1等于几` | 12 tokens，ids `[235274, 235340, 235274, 235409, 240663, ...]` | 6 tokens，ids `[235248, 235274, 235340, 235274, 131099, 236357]` |
| `choice question: Which tool should be used?` | 15 tokens，`choice`→21062 | 9 tokens，`choice`→6241 |

错误 token 序列喂给模型 → 决策结果巨大偏差。生产路径永远优先加载 `tokenizer.json`，不受影响。

### 本次加固

`build_gguf_tokenizer`（`src/mv/gguf.rs`）：`model=gpt2` 但 `pre` 为 `gemma`/`mmbert`（Metaspace 族）时改走 gemma 构建器（▁ Metaspace + byte_fallback）。**验证：该重建对 julia_1 与官方 tokenizer.json 逐 token 一致（5 组文本全 MATCH）**——即使 tokenizer.json 缺失，兜底路径现在也是正确的。

## 二、双模型对比测试（问题 2）

### 测试设置

- 输入构造：`[CLS] choice question: <question> [SEP] [MASK] opt0 [MASK] opt1 [MASK] opt2 [SEP] <state> [SEP]`（state 与 question 相同）
- julia：Rust `ModernBertModel`（Q8_0 GGUF，144M）；官方金标准 = HF fp32 safetensors + 官方 `julia/model.py`
- laya：Rust `ggmlc` 图解释器（Q8_0 GGUF，322M）；官方金标准 = HF safetensors + 官方 `laya` pip 包
- 两个模型对算术均为**官方声明的能力边界之外**（julia README 明确声明不能解代数方程；laya 是路由/分类模型）

### 用例 1：`1+1等于几`，options `["4", "3", "2"]`

**原始输入**
```json
{"decisionType": "choice", "state": "1+1等于几", "question": "1+1等于几", "options": ["4", "3", "2"]}
```

**原始输出**

| 模型 | scores | probabilities | 选择 |
|---|---|---|---|
| julia (Rust Q8) | `[-5.7413, -6.3848, -2.7016]` | `[0.0446, 0.0234, 0.9320]` | **"2"** |
| julia (官方 fp32) | `[-5.308, -6.097, -2.5805]` | `[0.0597, 0.0271, 0.9132]` | **"2"** ✅ 一致 |
| laya (Rust Q8) | `[-0.9021, 0.5363, -0.8681]` | `[0.1600, 0.6744, 0.1656]` | **"3"** |
| laya (官方 pip) | — | `{4: 0.1642, 3: 0.6667, 2: 0.1691}` | **"3"** ✅ 一致 |

### 用例 2：`10+11等于几`，options `["21", "22", "23"]`

**原始输入**
```json
{"decisionType": "choice", "state": "10+11等于几", "question": "10+11等于几", "options": ["21", "22", "23"]}
```

**原始输出**

| 模型 | scores | probabilities | 选择 |
|---|---|---|---|
| julia (Rust Q8) | `[-6.6099, 3.6914, -7.3261]` | `[0.0000, 0.9999, 0.0000]` | **"22"** |
| julia (官方 fp32) | `[-6.265, 3.5864, -7.5514]` | `[0.0001, 0.9999, 0.0000]` | **"22"** ✅ 一致 |
| laya (Rust Q8) | `[-0.2711, -0.6678, 0.0974]` | `[0.3207, 0.2157, 0.4636]` | **"23"** |
| laya (官方 pip) | — | `{21: 0.3191, 22: 0.2153, 23: 0.4656}` | **"23"** ✅ 一致 |

### 分析

1. **两个 Rust 实现都与各自官方参考对齐**（julia 与官方 fp32 的 logit 差 ~0.1-0.4 = Q8 量化误差；laya 概率差 <0.01）——实现本身无损。
2. **两个模型在算术上都不可靠，且失败方式不同**：
   - julia：`1+1` 选 "2"（0.93，错误但"接近"）；`10+11` 以 0.9999 的置信度选 "22"——**高置信度错误**，与官方调查报告（`decision_model_investigation_20261116.md`）的结论一致：这是模型本身的行为，官方 fp32 同样如此。
   - laya：`1+1` 选 "3"（0.67）；`10+11` 选 "23"（0.47）——概率分布平缓（最高仅 0.47-0.67），**低区分度**，没有给出虚假的高置信度。
3. **工程含义**：算术/多步推理类请求不应路由给决策模型（两者皆是）；决策模型适用于域内任务（工具路由、选项挑选、相关度打分、noul 判断）。`decision_decide` 工具描述已声明此边界。

### 六选项扩展测试的分析

1. **实现正确性再次确认**：4 个新用例 × 2 个模型，Rust 输出与各自官方参考全部一致（julia logit 差为 Q8 量化噪声，laya 概率差 <0.01）。
2. **选项数量改变行为**：三选项时 julia 对 `10+11` 选 "22"（0.9999，错误）；六选项（含 21）时选对 "21"（0.94）——softmax 归一化随候选集变化，"21" 的绝对 logit 一直最高，但三选项时 "22" 更高。**决策模型的答案依赖候选集构成**。
3. **不含正确答案时的行为差异显著**：
   - julia 对 `10+11` 以 **0.96 的高置信度**选 "20"（数值上最接近 21 的选项）——高置信度错误，且倾向"数值邻近"而非随机。
   - laya 全程概率平缓（最高 0.22-0.39），无虚假置信——调用方可通过置信度阈值识别"模型不确定"。
4. **工程含义（更新）**：除算术边界外，**不含正确答案的请求无法靠模型自身识别**（julia 依旧高置信）。若上游需要"都不对"的语义，应显式加入如 `"none of the above"` 选项或走 noul 类型判断，而不是依赖概率分布。
