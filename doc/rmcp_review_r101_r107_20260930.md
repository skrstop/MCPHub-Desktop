## 3. 测试覆盖补全（第 16 套件 `rmcp_gap_matrix_r107.py`，43 项）

此前 15 套件所有真实调用**只打 openapi 上游**（公网IP）；本套件补齐「每版本×每传输方式×每通道」：

- **A 组（15）**：5 协议版本 × 3 上游传输类型（**stdio=codegraph / streamable-http=Idea-mcp-server / openapi=公网IP查询**）× root 通道全生命周期（initialize 版本回显精确一致 + tools/list + 真实 tools/call）
- **B 组（6）**：3 上游类型 × 单服务器通道（2025-06-18 会话全生命周期 + 2026 无状态）真实调用
- **C 组（5）**：tasks 双代全链路——2025-11-25 core（客户端须声明扩展能力，未声明 -32021 为规范行为）与 2026 extension（ttlMs），tasks/result 终态载荷直出断言 + 已终态 cancel -32602
- **D 组（10）**：id null/string、invalid JSON 双模式、unknown method、completion -32601 双模式、2MB 大载荷、无 session 通知一致性、严格模式对照
- **E 组（4）**：bearer 开关 × 2026 无状态 + legacy 会话公网IP 真实调用（自动还原）
- **F 组（3）**：SEP-2243 修复回归——2026 声明头无 Mcp-Name 的 prompts/get / resources/read 宽松放行 + 严格拒绝

**版本协商语义澄清（重要）**：rmcp 3.4.1 设计即「2026-07-28 无 initialize 握手」——initialize 命名 2026 时按规范回退最新 legacy 版本 2025-11-25（service.rs `negotiate_protocol_version` 注释明示）。9-27 报告 TC-23「协商 2026」是旧手写实现行为，现行为符合 SDK/规范；套件断言已按此修正。真实工具调用每版本至少 5 种通道/模式组合，公网IP 上游 `isError:false` 全链路验证。
