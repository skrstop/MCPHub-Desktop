# 1.1.3011

## 修复

- **模型切换重载弹框**多处体验修复：
  - 行内顺序改为「标题 → 数量 → 状态徽章」，数量文案在前
  - 文档处理三条子进度条（内容读取 / 分段处理 / 语义计算）全程常驻显示，未开始的阶段显示占位（`—`），不再随阶段切换消失
  - 子条计数不再换行，弹框加宽（480px → 540px）
  - 行标题对齐原型：「RAG 文档」「Smart Routing 索引」
- **Smart Routing 重载顺序**：修复切换模型后 Smart 索引先于 RAG 文档完成的问题——模型加载后不再自动后台重索引 Smart，统一由重载流程在文档重嵌入完成后按序执行（同时消除 Smart 被重复索引两次的浪费）
- **修复 qwen3 架构嵌入模型向量完全错误（相关度搜索失效的根因）**：GGUF 前向中 GQA 分组注意力的 K/V 头复制方式错误——`Tensor::repeat` 是块平铺（q 头 j 映射到 kv 头 j%kv），而正确语义是逐头交错重复（q 头 j 映射到 kv 头 j/rep）。经 llama.cpp eval-callback 逐层指纹比对定位，修复后与 llama.cpp 参考实现的嵌入余弦相似度从 ≈0 恢复到 **1.0000**（逐层 sum 全部一致）。gemma / lfm2 架构同款问题一并修复。受影响模型：F2LLM V2-160M 等 qwen3 系嵌入模型——此前这些模型的向量检索基本不可用（所有分数挤在一起、语义排序错误）
- **切换模型时自动重置相关度阈值**：不同模型的余弦分数带差异很大（如 granite 97m 相关对 ≈0.82-0.88，F2LLM V2-160M ≈0.55-0.65），旧模型的阈值对新模型会把全部结果过滤掉。现在检测到模型切换时自动将 scoreThreshold 重置为 0（不过滤），并写日志提示按新模型重新调整
- **特殊 token 追加约定对齐 llama.cpp**：`tokenizer.ggml.add_eos_token` 缺省时不再默认追加 EOS（此前默认追加，会使 last-token 池化池化到 EOS 位置导致向量偏移）；GGUF 显式声明的值仍然生效
